# CANopen Node Emulator (Go)

一套**纯进程内、无真实总线硬件、无外部服务**的多节点 CANopen 通信与故障恢复
模拟器，用于在并发与故障注入下验证：

- 节点 NMT 状态管理与心跳监控的结论稳定性；
- SDO 对对象字典的读写（加速与分段传输、中断与重试）及可区分的失败原因；
- PDO 的映射、周期收发，以及总线错误 / 节点离线 / 恢复后的行为；
- 异常帧（重复、乱序、迟到）下不扩散错误状态，恢复后数据可解释且幂等。

## 目录结构

| 包 | 职责 |
|----|------|
| `canbus` | 软件 CAN 总线：广播、订阅、单调序号、注入 hook、bus-off 故障开关 |
| `od` | 线程安全对象字典：类型/权限/长度校验、原子多对象事务 `Tx` |
| `nmt` | NMT 从站状态机、主站命令（COB 0x000）、心跳生产者与消费者 |
| `sdo` | SDO 服务端/客户端：加速与分段 upload/download、abort、超时重试、取消 |
| `pdo` | TPDO 周期发送、RPDO 映射接收：去重、乱序丢弃、超时、故障冻结 |
| `node` | 将上述子系统组装成一个完整节点，并做 NMT 地址过滤 |
| `cmd/demo` | 本地可运行的多节点端到端演示 |

## 支持的协议范围

- **NMT**（CiA 301）：START(0x01)、STOP(0x02)、ENTER-PRE-OP(0x80)、
  RESET-NODE(0x81)、RESET-COMMUNICATION(0x82)；单播与广播（目标字节 0）；
  状态 INITIALISING / PRE-OPERATIONAL / OPERATIONAL / STOPPED。
- **心跳**：生产者周期发送 COB `0x700+id`，1 字节状态码；消费者按可配置
  超时检测在线/离线。
- **SDO**：默认单通道（请求 `0x600+id`、响应 `0x580+id`）；加速传输
  （≤4 字节）与分段传输（任意长度）；toggle 位、size indicated、n 字段均按
  CiA 301 §7.2.4 编解码；标准 abort code；本地传输超时可重试，支持
  `context` 取消。
- **PDO**：经典 CAN 0..8 字节映射（TPDO COB `0x180+id` 等），多个 OD
  条目映射到同一帧；周期发送与按超时的接收状态机。
- **对象字典类型**：INT8/16/32、UINT8/16/32、VISIBLE_STRING、DOMAIN；
  访问权限 RO / WO / RW / CONST。

不包含：块传输（block transfer）、SYNC 驱动的同步 PDO、LSS、CANopen FD、
Emergency(EMCY) 生产、节点守护（node guarding）。心跳消费者额外维护一个
本地 `OFFLINE` 观察状态（不上线，不影响远端从站自身 FSM）。

## 状态与异常规则

### NMT / 心跳

- 节点上电进入 INITIALISING 后自主进入 PRE-OPERATIONAL；未知命令或非法
  迁移被拒绝，**不改变当前状态**（无状态回退）。
- 地址过滤在接收方完成：只有目标字节等于本节点或 0（广播）的 NMT 帧生效。
- 心跳消费者只接受 COB `0x701..0x77F`、DLC=1、状态码合法且节点被跟踪的帧；
  其余帧一律忽略，不刷新截止时间。
- **重复或迟到的合法心跳只刷新截止时间，绝不产生错误**。
- 超时与恢复均为**边沿触发**：静默期间重复检查只产生一次 offline 事件；
  之后首个合法心跳产生一次 online 事件，且状态以该心跳携带的状态码为准。
- 一个节点超时不影响其它节点。

### SDO

失败以标准 SDO abort code 返回（`*od.AbortError`，实现了 `error`），原因
可区分：

| 场景 | abort code |
|------|-----------|
| 索引不存在 | `0x06020000` |
| 子索引不存在 | `0x06090011` |
| 读只写对象 | `0x06010001` |
| 写只读/常量对象 | `0x06010002` |
| toggle 位错误 | `0x05030000` |
| 命令说明符非法 | `0x05040001` |
| 数据类型/长度不匹配（声明长度不符） | `0x06070010` |
| 长度过大 / 过小 | `0x06070012` / `0x06070013` |
| 本地响应超时 | Go 错误 `sdo: response timeout`（非协议 abort，可重试） |

- **无部分写入**：分段下载时字典在最后一段到达前不被触碰；末段先校验声明
  长度与权限再整体提交（字典 `SetRaw` 先校验后落盘），失败则保留旧值。
  多对象/PDO 场景使用 `od.Tx` 事务：全部校验通过后一次性安装。
- **中断与重试**：分段传输中段响应丢失/超时时，客户端从
  “client initiate” 整体重启该传输（服务端在新 initiate 时干净复位），
  而不是重发相同 toggle 段；协议 abort 不重试，结论确定。重试次数与超时
  由 `sdo.Config` 配置。

### PDO

- 映射在构造时校验：映射不得超出 8 字节、不得重叠，否则创建失败。
- RPDO 依据总线分配的**单调序号**决策（同样输入结论稳定）：
  - `Seq < 上一次`：乱序/陈旧帧 → 丢弃；
  - `Seq == 上一次`：重复帧 → 忽略，不重复写 OD；
  - `Seq > 上一次`：经原子事务校验后整帧应用。
- 帧短于映射、映射对象不存在/只读等情况 → **整帧拒绝，无部分写入**，且
  不推进序号。
- 接收状态：`IDLE → ACTIVE`；超时进入 `STALE`（**保留最后一份可解释数据**）；
  bus-off 期间进入 `FAULTED`（帧被忽略、数据冻结）；故障清除后新帧恢复
  `ACTIVE`，恢复后数据仍可解释，重复应用幂等。
- TPDO 在 bus-off 期间持续运行，丢失的帧不报错；故障清除后自动恢复发送。

## 并发行为

- 所有共享状态（总线订阅、字典、NMT 状态、监控表、RPDO 序号/数据、SDO
  传输状态）均由互斥锁保护；总线投递期间持有订阅读锁，与 `Unsubscribe`
  的关闭操作互斥，杜绝“向已关闭通道发送”。
- 慢订阅者不阻塞总线：缓冲满时丢弃副本并计数（`Bus.Dropped()`），不影响
  其它订阅者。
- SDO 客户端用单订阅按响应 COB 解复用；每个节点单通道、传输串行化。
- 全测试套件在 `-race` 下通过。

## 故障注入

- `bus.SetFaulted(true/false)`：模拟 bus-off。开启期间发布的帧被计数但不
  投递；关闭后自动恢复。
- `bus.AddHook(func(Frame) Frame)`：可在投递前检查、篡改、丢弃任意帧
  （返回 `ID == canbus.Drop` 即丢弃），用于模拟丢帧、重复、乱序与
  SDO/心跳中断。

## 本地验证

要求 Go 1.25+（开发环境 Go 1.26）。无需任何硬件或外部依赖。

```bash
# 端到端演示：NMT、心跳、SDO 加速/分段、PDO、总线故障与恢复
go run ./cmd/demo

# 全量单元测试（竞态检测）
go test -race ./...

# 稳定性：重复运行
go test -race -count=10 ./...

go vet ./...
```

测试覆盖：并发多节点 NMT、心跳地址/重复/迟到/超时/恢复、SDO 加速与分段、
可区分 abort、段中断重试、无部分写入、PDO 去重/乱序/超时/故障冻结/恢复、
映射校验，以及多节点总线故障端到端恢复。测试通过 `t.Logf` 打印关键帧、
状态变化与判定依据，可用 `go test -race -v ./...` 查看。
